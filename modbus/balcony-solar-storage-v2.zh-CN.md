## 1 概述

本指南描述**CONOW 阳台光伏储能及一体机（v2 固件）的 Modbus RTU / TCP 接口**——
涵盖 CBE 系列（CBE2000 Pro）、Lyra 系列（Lyra 2500 AC、Lyra 2500 Pro）和 Atlas 系列（Atlas 6000 AC）。

与 [v1 寄存器表](balcony-solar-storage.zh-CN.md)相比，v2 固件带来：

- 监控区（10000–10081）：CT/电表数据、分相电网功率、每路 PV 串的电压/电流/
电量、设备上报的电池限制、SOH、序列号与固件版本。
- 控制区（10100–10190）：工作策略、工作模式、逆向功率限制、Modbus 超时、
基础负荷时段表、最多 8 个时段的手动充放电（TOU）时段表，以及时间校准
寄存器。
- 一体机上的 **Modbus TCP 直连**（端口 502），由**动态验证码**保护；RTU 与
TCP 可同时启用，写入遵循 RTU 优先的仲裁规则。
- **原子成组写入**——部分控制值必须在同一帧 FC 0x10 中一起写入。

### 固件版本检查

两套寄存器表**互斥**：设备只应答 v1 地址或 v2 地址。各机型支持 v2 寄存器表的最低固件版本：

| 机型 | 最低固件版本 |
| --- | --- |
| Lyra 系列 | 1.01.16 |
| CBE2000 Pro | 1.02.18 |
| Atlas 6000 AC | 1.01.08 |

低于上表版本的固件默认使用 v1 寄存器地址。不确定使用哪个版本寄存器地址时，连接后按以下方法检查：

1. 用 FC 0x03 读取固件版本字段 **10062（0x274E），数量 2**（10062–10063）。
2. 按应答结果选择指南：
   - **有应答**——说明固件已支持该寄存器区间：固件达到上表所列版本，设备使用 v2 寄存器表，继续使用本指南。
   - **无应答、超时，或返回 Modbus 异常**——说明固件不支持该寄存器区间：固件低于上表所列版本，请改用 [balcony-solar-storage.zh-CN.md](balcony-solar-storage.zh-CN.md)。

注意：

- 固件版本字段（10062–10063，U16[2] ASCII）**不应答单寄存器读取**——须在一帧中同时读取这两个寄存器。
- 序列号字段（10054–10061，U16[8] ASCII）有同样限制：须一次读完整 8 个寄存器。

### 从 v1 迁移

两版控制地址存在调整——已有 v1 集成请先更新映射，再执行写入：

| 功能 | v1 | v2 |
| --- | --- | --- |
| 交流充电功率限制 | 10100 | 10100——不变 |
| 放电功率限制 | 10101 | 10101——不变 |
| 备电 SoC | 10102 | 10102——不变 |
| 充放电方向 | 10105 | 10103 |
| 目标充放电功率 | 10106 | 10104 |
| 充放电截止 SoC | 10107 | 10105 |

v1 的顺序写规则（10106 → 10105 → 10107，FC 0x06）在 v2 **不适用**：10103–10106 须作为一组原子 FC 0x10 写入（仅方向 = 3 允许单寄存器写）。

v1 的离网输出开关（10103）与弃光开关（10104）在 v2 地址功能已变更——10103/10104 已是方向、功率寄存器；迁移这两项功能前先核对控制表。

监控寄存器同样重新分组——轮询前逐个地址对照 v2 表核实。

电网有功功率的符号约定也已调整：v1 上 CBE2000 Pro 正值=向电网馈电、负值=从电网取电，Lyra / Atlas 正值=从电网取电、负值=向电网馈电；v2 上所有机型统一为正值=从电网取电、负值=向电网馈电（10006、10013）。

### 传输与连接参数

| 参数           | 取值                                                                        |
| ------------ | ------------------------------------------------------------------------- |
| 传输方式         | RS-485 Modbus RTU，或 Modbus TCP（一体机，TCP 端口 **502**）                        |
| 串口参数（RTU）    | **38400** 波特率，8 位数据位，无校验，1 位停止位（8N1）                                      |
| 默认从站 / 单元 ID | **160（0xA0）**                                                            |
| 单元 ID 范围     | 128–176（0x80–0xB0）；ID 可在寄存器 **9984（0x2700）** 验证后读取和写入；更改后无需重新进行 TCP 验证   |
| 功能码          | 0x03 读 · 0x06 写单个 · 0x10 写多个                                              |
| 单次读取上限       | 一帧 FC 0x03 最多读取 **127** 个寄存器；更长的请求无应答。Modbus 规范上限为 125 个寄存器，建议按不超过 125 读取 |

### 验证码（一体机 Modbus TCP 直连）

**使用 Modbus RTU 无需验证；使用 Modbus TCP 须先在 App 中开启 TCP 开关并完成验证**——连接 TCP 后，将 CONOW App 设备详情页获取的 8 位十六进制验证码写入设备：

- 将其按 **uint32** 写入保持寄存器 **9985–9986（0x2701–0x2702）**，高字在前。
- 验证码是**动态的，每 120 秒刷新**，验证通过后停止刷新。若设备拒绝该验证码，请从 App 读取新验证码后重新写入。
- **验证错误锁定**：5 分钟内连续 5 次验证错误后，TCP 验证锁定 5 分钟——锁定期间无法完成验证，TCP 读写请求均以异常码 0x02 应答（仅读取单元 ID 寄存器 9984 例外）；请等待解锁后从 App 获取新验证码重新写入。
- 以下情况需要重新验证：App 中重新启用 Modbus 开关、适配器 MAC 地址变更，或手动刷新验证码。
- 设备通过以 **Modbus 异常**应答请求来要求验证——已连接但未验证的请求返回验证错误，未连接则无应答，两种情况需注意区分。一旦某次请求被正常应答，之后轮询**不会**再要求验证码。
- RS-485 上的 RTU（以及经 RS-485 转以太网网关的 Modbus TCP）无需验证码校验。

### RTU 与 TCP 并用（写优先级）

App 中的 **RTU 与 TCP 开关相互独立**，两个通道可同时开启。RTU 读指令（FC 0x03）可直接使用；TCP 的读写须先完成 9985–9986 验证。写帧（FC 0x06 / 0x10）遵循**单写者规则，RTU 优先**：

- RTU 持有写权限期间（10114 看门狗窗口内收到任意有效写帧），已验证的 TCP 写指令被拒绝——不应答、不执行；已验证的 TCP 读指令不受影响。
- RTU 通讯断开，或超过 10114 设定的时间未再写入后，写权限释放，已验证的 TCP 写指令才会生效。RTU 任意时刻的新写帧立即重新取得写权限；TCP 不存在抢占 RTU 的路径。
- 验证（9985–9986）只是 TCP 读写的前提，并不是取得写权限的手段——两者相互独立。

同一时间只由一个主站下发写指令。TCP 写指令收到异常 0x86（FC 0x06）或 0x90（FC 0x10）属于预期的写优先级保护行为，不是链路故障，建议按照实际需求开启一种控制方式。

### 硬件接线

接线方式与 v1 指南相同，端子定义与接线图见[硬件接口（v1 指南）](balcony-solar-storage.zh-CN.md#12-硬件接口)。

### 前提条件

设备必须已在 **CONOW ECO App** 中完成调试并至少上线一次——出厂未激活、从未上线的设备，RS-485 接口不响应任何请求。

1. 在 App 的 *设备 → 你的设备 → 设置* 中开启 *启用 Modbus 服务*；如需 TCP 直连，还须开启 TCP 开关；旧版 App 没有此开关时，改用 *设置 → 工作模式* 选择 *DIY 模式*。
2. 同一时刻只由一个主站下发写指令——见[RTU 与 TCP 并用](#rtu-与-tcp-并用写优先级)。

## 2 数据类型

| 类型 | 编码 |
| --- | --- |
| `uint16` | 1 个寄存器，无符号 |
| `int16` | 1 个寄存器，补码表示；符号含义见各寄存器说明 |
| `uint32` | 2 个寄存器，**大端序，高字在前** —— `value = (reg[n] << 16) \| reg[n+1]` |
| `string` | U16 数组，每个寄存器 2 个 ASCII 字符（高字节在前），不足补 0x00 |
| `hhmm` 时间 | 1 个寄存器：高字节=小时，低字节=分钟（例如 `06:30` → `0x06 0x1E` → `0x061E` = 1566） |
| 倍率 | 物理值 = 原始值 × 倍率（未注明时倍率为 1） |
| 枚举 / 布尔 | 见下方各寄存器的取值说明 |

## 3 寄存器表

三个区域，不连续：

| 区域 | 寄存器 | 访问 |
| --- | --- | --- |
| 监控 | **10000–10081**（0x2710–0x2761） | 只读，FC 0x03 |
| 控制 | **10100–10190**（0x2774–0x27CE） | 读 FC 0x03 · 写 FC 0x06 / 0x10——10103–10106 除外：仅整组 FC 0x10 原子写（方向 = 3 也可 FC 0x06 单写） |
| 协议 | 9984（单元 ID，读写）· 9985–9986（验证码，只写） | 见 3.12；流程见上文 |

与 v1 固件（对 38 个及以上寄存器的单次读取不作应答）不同，v2 固件支持整区读取——参考 Home Assistant 集成每轮用一帧 FC 0x03 读取整个监控区（82 个寄存器），再用一帧读取整个控制区（91 个寄存器）。若你的网关或工具处理长帧存在困难，可按以下分组边界拆分读取。

### 3.6 控制——实时强制充放电（10103–10106）

本组**明确不支持单寄存器写入**（唯一例外：方向值 3 允许用 FC 0x06 单独写入）。四个寄存器须写入**同一帧 FC 0x10**。本组数据断电丢失，且当**截止 SoC**或**时长**任一条件先达到时即结束。Modbus 超时后（见 10114）设备回到启用 Modbus 服务之前的 CONOW 平台运行模式。

10104 为**直出功率设定**：设备按设定值输出，不跟随负载。负载跟随行为由 App 中的工作模式（10107）选择，且前提是电表已连接。

| --- | --- | --- | --- | --- | --- |
| 10103 | 0x2777 | 充放电方向 | uint16 | — | 0 = 空闲 · 1 = 充电 · 2 = 放电 · 3 = 退出；方向值 3（退出）允许用 FC 0x06 单独写入 |

| 10105 | 0x2779 | 充放电截止 SoC | uint16 | % | 安全 SoC（10102） 至 100；放电时低于安全 SoC 的写入值自动按 10102 写入，不返回异常码 |
| 10106 | 0x277A | 充放电时长 | uint16 | 分钟 | 30 至 720；与截止 SoC 任一条件先到达即结束本次指令 |

## 4 帧示例

帧结构与 CRC-16（Modbus）与 v1 指南完全一致：从站 `0xA0`、功能码、数据、CRC 低字节在前。以下示例均为 RTU 帧；TCP 帧格式见 [Modbus TCP 帧格式（MBAP）](#modbus-tcp-帧格式mbap)。

**读取固件版本字段（版本检查，10062 × 2）：**

```
A0 03 27 4E 00 02 B7 D9
```

**读取实时数据（10000 × 12）：**

```
A0 03 27 10 00 0C 57 CF
```

**写单个寄存器——交流放电功率限制 700 W → 10101：**

```
A0 06 27 75 02 BC 8B 04
```

**原子组写入——强制放电 500 W，直至 SoC 80% 或 120 分钟（FC 0x10，寄存器 10103–10106）：**

```
A0 10 27 77 00 04 08  00 02 01 F4 00 50 00 78  84 66
│  │  └───┘ └───┘ │   └───┘ └───┘ └───┘ └───┘  └───┘
│  │  │     │     │   │     │     │     │      └── CRC-16
│  │  │     │     │   │     │     │     └── 寄存器 10106：0x0078（120 分钟）
│  │  │     │     │   │     │     └── 寄存器 10105：0x0050（80%）
│  │  │     │     │   │     └── 寄存器 10104：0x01F4（500 W）
│  │  │     │     │   └── 寄存器 10103：0x0002（放电）
│  │  │     │     └── 字节数：8（4 个寄存器 × 2 字节）
│  │  │     └── 数量：4 个寄存器
│  │  └── 起始地址：0x2777（10103）
│  └── FC 0x10
└── 从站 160（0xA0）
```

### Modbus TCP 帧格式（MBAP）

TCP 下相同的 PDU 封装在 7 字节 MBAP 头内，**没有 CRC**——完整性由 TCP 传输层保证。

| MBAP 字段 | 长度 | 取值 |
| --- | --- | --- |
| 事务 ID | 2 字节 | 主站自选；应答原样返回 |
| 协议 ID | 2 字节 | `0x0000`（Modbus） |
| 长度 | 2 字节 | 后续字节数（单元 ID + PDU） |
| 单元 ID | 1 字节 | 设备单元 ID——默认 `0xA0`（寄存器 9984） |

**写验证码（TCP 直连）——验证码** `1A2B3C4D` **→ 9985–9986：**

```
00 01  00 00  00 0B  A0  10  27 01  00 02  04  1A 2B 3C 4D
└───┘  └───┘  └───┘  │   │   └───┘  └───┘  │   └─────────┘
│      │      │      │   │     │      │    │   验证码 0x1A2B3C4D
│      │      │      │   │     │      │    └── 字节数：4
│      │      │      │   │     │      └── 数量：2 个寄存器
│      │      │      │   │     └── 起始地址：0x2701（9985）
│      │      │      │   └── FC 0x10
│      │      │      └── 单元 ID：160（0xA0）
│      │      └── 长度：11 字节（单元 ID + PDU）
│      └── 协议 ID：0x0000（Modbus）
└── 事务 ID：0x0001——应答原样返回
```

应答帧回显头部，长度为 6：`00 01 00 00 00 06 A0 10 27 01 00 02`。

自行校验任意帧的 CRC：

```sh
python3 - <<'PY'
def crc16(data):
    c = 0xFFFF
    for b in data:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0xA001 if c & 1 else c >> 1
    return c
frame = bytes.fromhex("A0102777000408" "0002" "01F4" "0050" "0078")
print(f"{crc16(frame):04X}")   # 先附加低字节，再附加高字节
PY
```

**异常响应**——出错时设备以 `[从站][功能码+0x80][异常码][CRC]` 应答，异常码含义见 [6.1 Modbus 异常码](#61-modbus-异常码)。

### 命令行快速验证

上文的帧示例为原始协议字节。初次联调也可以直接使用标准 Modbus 客户端驱动设备，例如 [mbpoll](https://github.com/epsilonrt/mbpoll) 或 [pymodbus](https://github.com/pymodbus/pymodbus)。以下两个示例通过 RS-485 RTU 执行[固件版本检查](#固件版本检查)——用 FC 0x03 读取 10062–10063——RTU 无需验证码。

```sh
# mbpoll —— /dev/ttyUSB0 上的 RTU，从站 160（0xA0），38400 8N1
# -P none 必须显式指定：mbpoll 默认使用偶校验
mbpoll -m rtu -a 160 -b 38400 -P none -t 4 -0 -r 10062 -c 2 -1 /dev/ttyUSB0
# 在 -t 4 后追加 ":string" 可按 ASCII 字符打印寄存器内容
```

```python
# pymodbus 3.x —— pip install pymodbus
import struct

from pymodbus.client import ModbusSerialClient

client = ModbusSerialClient(
    port="/dev/ttyUSB0",
    baudrate=38400,
    bytesize=8,
    parity="N",
    stopbits=1,
)
client.connect()
rr = client.read_holding_registers(address=10062, count=2, slave=160)
if not rr.isError():
    print(struct.pack(">HH", *rr.registers).decode())  # 4 个 ASCII 字符
client.close()
```

Modbus TCP 直连时须先完成[验证码](#验证码一体机-modbus-tcp-直连)写入。以验证码 `1A2B3C4D` 为例：

```sh
# mbpoll —— 按 uint32 写入验证码，高字在前（9985 = 0x1A2B，9986 = 0x3C4D）
mbpoll -m tcp -a 160 -t 4 -0 -r 9985 -1 192.168.1.100 6699 15629
```

pymodbus 的等价写法是在 `ModbusTcpClient("192.168.1.100", port=502)` 上执行 `client.write_registers(address=9985, values=[0x1A2B, 0x3C4D], slave=160)`。

## 5 重要注意事项

1. **Modbus 与 App 的优先级。** Modbus 与 App/云端是两条独立控制路径：

   Modbus 活跃期间设备脱离 App 端工作模式，只执行 Modbus 指令；Modbus 停止写入并超过 10114 超时后，设备恢复启用 Modbus 服务前的 CONOW 平台运行模式。
2. **组写入规则。** 需原子写入的指令（实时控制）须按寄存器地址一次写入。
3. **时段表数量一致。** 只写入实际使用的前 N 个时段，并将数量寄存器（10124 / 10149）设为 N——设备只执行前 N 个时段。
4. **工作模式先读后写。** 写 10107 前建议先读取当前值，再写入目标值。
5. **持久性。** 10103–10106、10121–10122 与 10190 断电丢失；控制区其余寄存器均断电保持。
6. **CRC 错误的帧被直接丢弃。** 超时后最多重试 3 次，间隔至少 500 毫秒，连续 3 次超时视为链路异常。实时数据轮询不快于每 1 秒一次；一次读或写多个寄存器时，轮询间隔建议不低于 2 秒；能量控制类寄存器不快于每 5 秒一次，避免高频轮询整张寄存器表。
7. **保持前提条件。** 设备需在 CONOW ECO App 完成过调试，并已开启*启用 Modbus 服务*——未完成调试的设备无论固件版本如何都不响应任何请求；关闭*启用 Modbus 服务*后，RTU 读写返回异常码 0x06（[6.1 Modbus 异常码](#61-modbus-异常码)）。
8. **看门狗只计写帧。** 10114 看门狗仅计有效写帧（FC 0x06 / 0x10）——轮询读帧不会重置计时。若主站最后一条指令为方向 = 空闲（10103 = 0），设备持久保持该状态、不回退；只有新指令或停用 Modbus 服务才会改变。
9. **同一时刻只有一个写者。** RTU 与 TCP 同时开启时，写入遵循[RTU 与 TCP 并用](#rtu-与-tcp-并用写优先级)中的 RTU 优先规则；TCP 写指令被拒（0x86 / 0x90）属于正常的写优先级策略，并非故障。

请先根据故障现象排查，再参考对应章节。

| 症状                 | 第一步检查                                                           | 说明 / 参考                                                                              |
| ------------------ | --------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 设备完全无应答            | App 中 Modbus 开关是否开启；从站地址 / 单元 ID 是否与 9984 当前值一致                 | 开关关闭时 RTU 读写返回异常码 0x06（[6.1 Modbus 异常码](#61-modbus-异常码)）；默认 0xA0（[传输与连接参数](#传输与连接参数)）                                          |
| RTU 偶发无应答或校验错      | CRC-16 计算（多项式 0xA001）与串口参数 38400-8-N-1                          | CRC 错误帧被丢弃且不回应——先检查 CRC，再确认接线与地址是否正确                                                  |
| 读取 128 个及以上寄存器时无应答 | 单次读取是否超过 127 个寄存器                                               | 一帧 FC 0x03 最多 127 个寄存器（[单次读取上限](#传输与连接参数)）                                           |
| TCP 无响应、验证错误或写入无效  | 先检查 TCP 开关、网络与单元 ID；返回验证错误则重新校验 9985–9986；验证后写入仍被拒绝，确认 RTU 写优先规则 | 未连接无应答；已连接未验证返回验证错误；（[验证码](#验证码一体机-modbus-tcp-直连)、[RTU 与 TCP 并用](#rtu-与-tcp-并用写优先级)） |
| 写入被忽略或返回异常         | 写入值是否在寄存器范围内                                                    | 超范围写入以异常 0x03 拒绝（[6.1 Modbus 异常码](#61-modbus-异常码)）                                                     |
| 断开后设备行为变化          | 看门狗 10114 是否启用                                                  | 10114 = 0 时设备保持工作模式；设定超时后回到启用 Modbus 服务前的 CONOW 平台模式（[注意事项](#5-重要注意事项)）              |

### 6.1 Modbus 异常码

读写只使用 FC 0x03 / 0x06 / 0x10，标准异常码（0x01–0x03）只在这三种功能码的应答中出现；出错时设备以 `[从站][功能码+0x80][异常码][CRC]` 应答：

| 异常码 | 含义 | 典型原因 |
| --- | --- | --- |
| 0x01 | 非法功能 | 功能码不支持（读写仅支持 FC 0x03 / 0x06 / 0x10） |
| 0x02 | 非法数据地址 | 寄存器不存在，或该机型不支持；TCP 验证锁定期间读写均返回 0x02（读 9984 除外） |
| 0x03 | 非法数据值 | 写入值超范围 |

0x04 / 0x05 是 TCP 直连验证层返回的设备自定义状态码，并非 FC 0x03 / 0x06 / 0x10 的标准读写异常应答；验证层场景见[验证码](#验证码一体机-modbus-tcp-直连)：

| 异常码 | 含义 | 典型原因 |
| --- | --- | --- |
| 0x04 | MAC 地址改变（设备自定义） | TCP 验证码因适配器 MAC 地址改变而失效——重新写入验证码 |
| 0x05 | 手动刷新（设备自定义） | 验证码被手动刷新失效后，再通过 TCP 访问时返回——写入新验证码 |

0x06（设备自定义）仅在 Modbus RTU 下返回——App 中关闭*启用 Modbus 服务*开关后，读写寄存器即以 0x06 应答：

| 异常码 | 含义 | 典型原因 |
| --- | --- | --- |
| 0x06 | Modbus 服务未启用（设备自定义） | App 中*启用 Modbus 服务*开关已关闭——重新开启后再读写 |
